# 2. 系统架构

## 2.1 整体架构

Arroyo 采用分布式架构设计，由多个组件协同工作，实现高效的流处理。系统的主要组件包括：

1. **API 服务器**：提供 REST API 接口，用于管理流处理作业和系统资源
2. **控制器**：负责作业调度、资源分配和系统协调
3. **编译器服务**：将 SQL 查询编译为可执行的流处理程序
4. **工作节点**：执行流处理任务的计算单元
5. **节点服务器**：管理工作节点的生命周期和资源
6. **Web UI**：提供图形化界面，用于监控和管理系统

## 2.2 组件详解

### 2.2.1 API 服务器

API 服务器是 Arroyo 的前端接口，提供 REST API 供用户和其他系统交互。主要功能包括：

- 接收和验证 SQL 查询
- 管理流处理作业（创建、更新、删除、重启）
- 管理连接器和数据源
- 提供作业状态和指标查询
- 用户认证和授权

API 服务器使用 Axum 框架实现，支持异步处理和高并发请求。

### 2.2.2 控制器

控制器是 Arroyo 的核心组件，负责整个系统的协调和管理。主要功能包括：

- 作业调度和资源分配
- 工作节点的注册和管理
- 检查点协调和状态管理
- 故障检测和恢复
- 系统指标收集

控制器支持多种调度器实现，包括：

- **Node 调度器**：在单节点环境中调度作业
- **Kubernetes 调度器**：在 Kubernetes 集群中调度作业
- **嵌入式调度器**：在嵌入式环境中调度作业
- **进程调度器**：使用本地进程调度作业

### 2.2.3 编译器服务

编译器服务负责将 SQL 查询编译为可执行的流处理程序。主要功能包括：

- SQL 解析和验证
- 查询计划生成和优化
- 代码生成
- UDF（用户定义函数）编译和管理

编译器服务使用 DataFusion 作为 SQL 解析和优化的基础，并扩展了流处理特定的功能。

### 2.2.4 工作节点

工作节点是执行流处理任务的计算单元。每个工作节点可以运行多个任务，处理数据流的不同部分。主要功能包括：

- 数据处理和转换
- 状态管理和检查点
- 与其他工作节点的数据交换
- 指标收集和报告

工作节点采用 Actor 模型设计，每个任务作为一个独立的 Actor 运行，提高了系统的并发性和容错性。

### 2.2.5 节点服务器

节点服务器管理工作节点的生命周期和资源。主要功能包括：

- 工作节点的创建和销毁
- 资源监控和管理
- 与控制器的通信
- 日志收集和报告

### 2.2.6 Web UI

Web UI 提供图形化界面，用于监控和管理 Arroyo 系统。主要功能包括：

- 作业创建和管理
- 作业状态和指标可视化
- 数据流可视化
- 系统配置和管理

Web UI 使用现代前端技术栈构建，提供直观、响应式的用户体验。

## 2.3 数据流

在 Arroyo 中，数据流经过以下步骤处理：

1. **数据摄取**：从各种数据源（如 Kafka、Kinesis、文件系统等）摄取数据
2. **数据转换**：应用各种转换操作（如过滤、映射、聚合、窗口等）
3. **状态管理**：维护和更新处理状态
4. **检查点**：定期创建状态检查点，确保容错性
5. **数据输出**：将处理结果输出到各种目标（如 Kafka、数据库、文件系统等）

## 2.4 状态管理

Arroyo 提供强大的状态管理机制，确保流处理作业的可靠性和容错性。主要特性包括：

- **分布式状态**：状态分布在多个工作节点上，提高并行性
- **检查点**：定期创建状态检查点，用于故障恢复
- **状态后端**：支持多种状态存储后端，如内存、本地存储和分布式存储
- **增量检查点**：优化检查点性能，减少存储和网络开销

## 2.5 容错机制

Arroyo 设计了多层容错机制，确保系统的可靠性：

- **检查点恢复**：从最近的检查点恢复状态，确保数据一致性
- **任务重启**：自动重启失败的任务
- **节点故障处理**：在节点故障时重新分配任务
- **数据源重放**：支持从数据源重放数据，确保数据不丢失
